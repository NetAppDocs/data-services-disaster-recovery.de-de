= Ändern eines Replikationsplans in NetApp Disaster Recovery
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/use/


[role="lead"]
In NetApp Disaster Recovery können Sie die Auswirkungen eines Replikationsplans auf die Compliance-Zeitvorgaben anpassen, um sicherzustellen, dass Failover Tests erfolgreich abgeschlossen werden.

Sie können die Compliance-Zeit ändern und die Auswirkungen eines Test-Failovers prüfen. Zum Bearbeiten der Planwiederholung, der Failover-Zuordnungen oder der zugehörigen Ressourcen müssen Sie den Replikationsplan löschen und einen neuen erstellen.



[[modifiable-fields]]
== Modifizierbare Felder

* *Auswirkungen auf die Compliance-Zeit*: Wenn ein Replikationsplan erstellt wird, erstellt der Dienst standardmäßig einen Compliance-Zeitplan.  Die Standard-Compliance-Zeit beträgt 30 Minuten.  Um diese Zeit zu ändern, können Sie den Zeitplan im Replikationsplan bearbeiten.
* *Auswirkungen des Failovers testen*: Sie können einen Failover-Prozess bei Bedarf oder nach Zeitplan testen. Damit können Sie das Failover von VMs oder Kubernetes-Applikationen zu einem im Replikationsplan angegebenen Ziel testen.
+
Ein Test Failover erstellt ein FlexClone Volume und bindet bei VMware Workloads den Datenspeicher ein und verschiebt den Workload auf diesem Datenspeicher. Ein Test Failover hat _keine_ Auswirkungen auf Produktions-Workloads, die auf der Testumgebung verwendete SnapMirror Beziehung und geschützte Workloads, die weiterhin normal funktionieren müssen.



Basierend auf dem Zeitplan wird der Failover-Test ausgeführt und stellt sicher, dass die Workloads an das im Replikationsplan angegebene Ziel verschoben werden.



[[modify-a-replication-plan]]
== Einen Replikationsplan ändern

. Im Menü „Notfallwiederherstellung“ ist *Replikationspläne* auszuwählen.
+
image:dr-plan-list.png["Screenshot der Liste der Replikationspläne"]

. Im Menü *Aktionen* image:icon-horizontal-dots.png["Horizontale Punkte Aktionsmenü"] erfolgt anschließend die Auswahl von *Zeitpläne bearbeiten*.
. Hier wird festgelegt, wie häufig Disaster Recovery die Test-Compliance in Minuten überprüfen soll.
. Um zu überprüfen, ob Ihre Failover-Tests fehlerfrei sind, aktivieren Sie *Führen Sie Failover monatlich aus*.
+
.. Wählen Sie den Tag des Monats und die Uhrzeit aus, zu der diese Tests ausgeführt werden sollen.
.. Geben Sie das Datum im Format JJJJ-MM-TT ein, an dem der Test beginnen soll.
+
image:dr-plan-schedule-edit2.png["Screenshot, der zeigt, wo Sie Zeitpläne bearbeiten können"]



. *On-Demand-Snapshot für geplantes Test-Failover*: Mit diesem Kontrollkästchen wird vor dem Start des automatisierten Test-Failovers ein neuer Snapshot erstellt.
. Um die Testumgebung nach Abschluss des Failovertests zu bereinigen, aktivieren Sie *Automatisch bereinigen nach Testfailover* und geben Sie die Anzahl der Minuten ein, die Sie warten möchten, bevor die Bereinigung beginnt.
+

NOTE: Dieser Prozess löscht das erstellte FlexClone Volume und entfernt die temporären Testressourcen vom Teststandort. Bei VMware Workloads werden außerdem die temporären VMs abgemeldet und die temporären Datastores ausgehängt.

. Wählen Sie *Speichern*.




[[delete-or-disable-a-replication-plan]]
== Replikationsplan löschen oder deaktivieren

Sie können einen Replikationsplan vorübergehend deaktivieren, wenn Sie beispielsweise Updates einspielen oder Wartungsarbeiten durchführen müssen, die die Integrität des Replikationsplans und der zugehörigen Vorgänge beeinträchtigen würden.

Sie können einen Replikationsplan auch löschen, wenn Sie ihn nicht mehr benötigen oder wesentliche Änderungen daran vornehmen müssen, die über den Rahmen einer Änderung hinausgehen.

.Schritte
. Im Menü „Notfallwiederherstellung“ ist *Replikationspläne* auszuwählen.
+
image:dr-plan-list.png["Screenshot der Liste der Replikationspläne"]

. Zum Deaktivieren oder Löschen des gewünschten Replikationsplans wird dessen Menü *Actions* image:icon-horizontal-dots.png["Horizontale Punkte Aktionsmenü"] verwendet.
. *Löschen* oder *Deaktivieren* stehen zur Auswahl.
. Im Pop-up finden Sie die Anweisungen. Zum Deaktivieren dient die Option *Deaktivieren*.
+
Wenn Sie *Delete* auswählen, wählen Sie die zugehörigen Snapshots oder Metadaten aus, die zusammen mit dem Replikationsplan gelöscht werden sollen: *Delete primary snapshots*, *Delete secondary snapshots* oder *Delete snapshot metadata*. Geben Sie im Textfeld "delete" ein, um den Vorgang zu bestätigen, und wählen Sie dann *Delete*.
