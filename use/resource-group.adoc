= Eine Ressourcengruppe in NetApp Disaster Recovery erstellen
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/use/


[role="lead"]
Nachdem Sie Ressourcen zu Standorten in NetApp Disaster Recovery hinzugefügt haben, können Sie Ressourcengruppen erstellen, um VMs, Datastores oder Kubernetes Cluster als Einheit zu organisieren. Mit Ressourcengruppen können Sie abhängige Ressourcen in logischen Gruppen zusammenfassen, die Ihren Anforderungen entsprechen. Beispielsweise können Sie VMs für eine Applikation gruppieren oder Applikationen mit ähnlichen Ebenen zusammenfassen. Ressourcengruppen können auch verzögerte Startreihenfolgen umfassen, die während der Wiederherstellung ausgeführt werden, damit die Ressourcen in der richtigen Reihenfolge starten.

*Erforderliche NetApp Console-Rolle* Für die Ausführung dieser Aufgabe ist die Rolle „Superadministrator“, „Administrator für Notfallwiederherstellung“ oder „Anwendungsadministrator für Notfallwiederherstellung“ erforderlich. link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-disaster-rec-roles.html["Erfahren Sie mehr über Benutzerrollen und Berechtigungen in NetApp Disaster Recovery"^]. link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["Erfahren Sie mehr über die Zugriffsrollen der NetApp Console für alle Dienste"^].

*Über diese Aufgabe*

Sie können VMs selbst oder VMs in Datenspeichern gruppieren.

Sie können Ressourcengruppen mit den folgenden Methoden erstellen:

* Über die Option „Ressourcengruppen“
* Während Sie einen Notfallwiederherstellungs- oder Replikationsplan erstellen. Wenn Sie viele VMs haben, die von einem Quell-vCenter-Cluster gehostet werden, kann es für Sie einfacher sein, die Ressourcengruppen während der Erstellung des Replikationsplans anzulegen. Anweisungen zum Erstellen von Ressourcengruppen während der Erstellung eines Replikationsplans finden Sie unter link:task-replication-plan-vmware.html["Erstellen eines Replikationsplans"].



TIP: Jede Ressourcengruppe kann eine oder mehrere VMs, Datenspeicher oder Kubernetes-Cluster enthalten. Die VMs werden entsprechend der Reihenfolge eingeschaltet, in der Sie sie im Replikationsplan aufnehmen. Die Reihenfolge lässt sich ändern, indem die VMs oder Datenspeicher in der Ressourcengruppenliste nach oben oder unten gezogen werden.



[[about-resource-groups]]
== Informationen zu Ressourcengruppen

Mit Ressourcengruppen können Sie VMs, Datastores oder Kubernetes-Anwendungen zu einer einzigen Einheit zusammenfassen.

Beispielsweise könnte eine Point-of-Sale-Anwendung mehrere VMs für Datenbanken, Geschäftslogik und Storefronts verwenden.  Sie können alle diese VMs mit einer Ressourcengruppe verwalten.  Richten Sie Ressourcengruppen ein, um Replikationsplanregeln für die VM-Startreihenfolge, Netzwerkverbindung und Wiederherstellung aller für die Anwendung benötigten VMs anzuwenden.



[[how-resource-groups-work]]
=== Wie Ressourcengruppen funktionieren

Disaster Recovery schützt VMs, indem die zugrunde liegenden ONTAP Volumes und LUNs repliziert werden, die die VMs in der Ressourcengruppe hosten. Dazu fragt das System vCenter nach dem Namen jedes Datastore, das VMs in einer Ressourcengruppe hostet. Disaster Recovery identifiziert dann das Quell-ONTAP Volume oder die Quell-LUN, die dieses Datastore hostet. Der gesamte Schutz erfolgt auf ONTAP Volume Level mithilfe der SnapMirror Replikation.

Wenn VMs in der Ressourcengruppe auf verschiedenen Datastores gehostet werden, verwendet Disaster Recovery eine der folgenden Methoden, um einen datenkonsistenten Snapshot der ONTAP Volumes oder LUNs zu erstellen.

[cols="30,65a"]
|===
| Relativer Standort von FlexVol -Volumes | Snapshot-Replikationsprozess 


| Mehrere Datenspeicher – FlexVol -Volumes im *gleichen SVM*  a| 
* ONTAP -Konsistenzgruppe erstellt
* Snapshots der Konsistenzgruppe erstellt
* Volume-bezogene SnapMirror -Replikation durchgeführt




| Mehrere Datenspeicher – FlexVol -Volumes in *mehreren SVMs*  a| 
* ONTAP API: `cg_start`. Versetzt alle Volumes in den Ruhezustand, damit Snapshots erstellt werden können, und initiiert Volume-bezogene Snapshots aller Ressourcengruppen-Volumes.
* ONTAP -API: `cg_end` .  Setzt die E/A auf allen Volumes fort und aktiviert die Volume-bezogene SnapMirror Replikation, nachdem Snapshots erstellt wurden.


|===


[[best-practices-for-resource-groups]]
== Bewährte Verfahren für Ressourcengruppen

Beim Erstellen von Ressourcengruppen sind die folgenden Szenarien zu berücksichtigen:

* Vor dem Hinzufügen von Datastores oder Namespaces zu Ressourcengruppen sollte eine manuelle Identifizierung initiiert oder eine geplante Identifizierung abgewartet werden. Dadurch ist sichergestellt, dass die VMs identifiziert und in der Ressourcengruppe aufgeführt sind. Ohne Start einer manuellen Identifizierung werden die Ressourcen in der Ressourcengruppe möglicherweise nicht aufgeführt.
* Im Datenspeicher muss sich mindestens eine Ressource (VM oder Namespace) befinden. Wenn sich keine Ressourcen im Datenspeicher befinden, identifiziert Disaster Recovery den Datenspeicher nicht.
* Ein einzelner Datenspeicher sollte keine VMs hosten, die durch mehr als einen Replikationsplan geschützt sind.
* Geschützte und ungeschützte Ressourcen dürfen nicht auf demselben Datastore gehostet werden. Wenn geschützte und ungeschützte Ressourcen auf demselben Datastore gehostet werden, können die folgenden Probleme auftreten:
+
** Da Disaster Recovery SnapMirror verwendet und das System ganze ONTAP Volumes repliziert, wird die genutzte Kapazität dieses Volumes für die Lizenzierung berücksichtigt. In diesem Fall wird der von geschützten und ungeschützten VMs belegte Volume-Speicherplatz in diese Berechnung einbezogen.
** Wenn für die Ressourcengruppe und ihre zugehörigen Entitäten ein Failover zum Disaster Recovery Standort erforderlich ist, sind nach dem Failover Prozess alle ungeschützten Ressourcen (VMs oder Namespaces, die nicht Teil der Ressourcengruppe sind, aber auf dem ONTAP Volume gehostet werden) am Quellstandort nicht mehr vorhanden, was zum Ausfall ungeschützter VMs am Quellstandort führt. Außerdem startet Disaster Recovery diese ungeschützten Ressourcen nicht am Failover Standort.


* Um eine Ressource zu schützen, muss sie Teil einer Ressourcengruppe sein.


*EMPFEHLUNG*: Organisieren Sie Ihre VMs vor der Bereitstellung von NetApp Disaster Recovery, um eine unkontrollierte Ausbreitung der Datenspeicher zu vermeiden. Platzieren Sie VMs, die Schutz benötigen, auf einer Teilmenge der Datenspeicher und VMs, die nicht geschützt werden sollen, auf einer anderen Teilmenge der Datenspeicher. Stellen Sie sicher, dass die VMs auf einem bestimmten Datenspeicher nicht durch unterschiedliche Replikationspläne geschützt werden.

[role="tabbed-block"]
====
.vCenters
--
.Schritte
. In Notfallwiederherstellung wählen Sie in der Seitenleiste **Ressourcengruppen** aus.
. Im Dropdown-Menü nach *VMware* filtern.
+
image::site-type-toggle.png[Screenshot der Umschaltung des Website-Typs]

. Die Auswahl von *Ressourcengruppen* erfolgt im Menü „Notfallwiederherstellung“.
. Wählen Sie *Hinzufügen*.
. Geben Sie einen Namen für die Ressourcengruppe ein.
. Wählen Sie den Quell-vCenter-Cluster aus, in dem sich die VMs befinden.
. Wählen Sie je nach gewünschter Suchmethode entweder *Virtuelle Maschinen* oder *Datenspeicher* aus.
. Wählen Sie die Registerkarte *Ressourcengruppen hinzufügen*.  Das System listet alle Datenspeicher oder VMs im ausgewählten vCenter-Cluster auf.  Wenn Sie *Datenspeicher* ausgewählt haben, listet das System alle Datenspeicher im ausgewählten vCenter-Cluster auf.  Wenn Sie *Virtuelle Maschinen* ausgewählt haben, listet das System alle VMs im ausgewählten vCenter-Cluster auf.
. Wählen Sie auf der linken Seite der Seite „Ressourcengruppen hinzufügen“ die VMs aus, die Sie schützen möchten.
+
image:dr-resource-groups-add.png["Screenshot der Seite „Ressourcengruppen hinzufügen“"]

+
image:dr-resource-groups-datastores-add.png["Screenshot der Seite „Ressourcengruppen hinzufügen“"]

. Ändern Sie optional die Reihenfolge der VMs auf der rechten Seite, indem Sie jede VM in der Liste nach oben oder unten ziehen.  Die VMs werden basierend auf der Reihenfolge eingeschaltet, in der Sie sie einschließen.
. Wählen Sie *Hinzufügen*.


--
.Kubernetes
--
.Schritte
. In Notfallwiederherstellung wählen Sie in der Seitenleiste **Ressourcengruppen** aus.
. Im Dropdown-Menü nach *Kubernetes* filtern.
+
image::site-type-toggle.png[Screenshot der Umschaltung des Website-Typs]

. Wählen Sie *Hinzufügen*.
. Geben Sie einen **Namen** für die Ressourcengruppe ein und wählen Sie den Kubernetes **Cluster** aus dem Dropdown-Menü aus.
. Wählen Sie die *Namespaces* aus, die der Ressourcengruppe hinzugefügt werden sollen.
. Die *Ressourcentypen* klassifizieren. Standardmäßig ist die Auswahl „Alle einschließen“ aktiviert, was mehrere Ressourcentypen bezeichnet.
. Optional können Sie *Label-Selektoren* einbeziehen.
+
image:kubernetes-resource-group.png["Screenshot vom Hinzufügen einer Kubernetes-Ressourcengruppe"]

. Optional können Sie *+ Cluster-scoped resources* auswählen, um Ressourcen hinzuzufügen, die nicht an einen Namespace gebunden sind. Wenn Sie diese Option wählen, wählen Sie die *Group*, *Version*, *Kind* und optional beliebige Label-Selektoren aus. Wählen Sie **Add resource** aus.
+
image:kubernetes-cluster-scoped.png["Screenshot der Hinzufügung von Kubernetes-Ressourcen mit Clusterbezug"]

. Wählen Sie **Hinzufügen**.
